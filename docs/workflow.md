# Data Processing Workflow

## Overview

The system operates through two main workflow paths
that share a common JSON storage layer on Google Drive.

- **Path 1** — Source data management and JSON generation
- **Path 2** — Participant matching, progression tracking, and analysis

Both paths are triggered through custom menu interfaces
in Google Sheets.

---

## Path 1 — Source Data Management

This path handles the creation and maintenance of
structured JSON datasets from source spreadsheets.

```text
Source data sheet configured with column ranges
        ↓
Component A triggered via custom menu
        ↓
Column ranges read from source sheet
        ↓
Participant IDs extracted into A_data
Source metadata extracted into B_to_H_data
        ↓
JSON dataset generated or updated on Google Drive
        ↓
Dataset ready for Path 2 processing
```

### Step 1 — Configuration

The operator configures the column range to process
by entering start and end column letters in designated cells.

An existing JSON filename can be specified to update
an existing dataset, or left empty to create a new file.

### Step 2 — Data Extraction

Component A reads the configured column ranges
from the source sheet.

For each column:
- participant IDs are extracted from rows 8 onwards (A_data)
- source metadata is extracted from rows 1 to 7 (B_to_H_data)
- empty values are filtered from A_data

### Step 3 — JSON Generation or Update

The extracted data is written to a JSON file on Google Drive.

If an existing filename is specified:
- the file is updated with the new column data
- other columns in the file are not affected

If no filename is specified:
- a new file is created with a date-based filename
- the filename is written back to the configuration cell

### Step 4 — Source Removal (when needed)

Obsolete source columns can be removed from the JSON dataset
by specifying the target column in the configuration cell.

The specified column entry is deleted from the JSON file
without affecting other source columns.

---

## Path 2 — Participant Matching and Progression Tracking

This path handles matching of participant records against
the historical JSON dataset and tracks progression
through engagement steps.

```text
Sample participant IDs prepared in input sheet
        ↓
Component B triggered via custom menu
        ↓
JSON classification files loaded from Google Drive
        ↓
Sample dataset generated from multiple source sheets
        ↓
Participant IDs matched against JSON source data
        ↓
Matched results written to step-specific output sheets
        ↓
Unmatched records handled separately
        ↓
Time tracking and work log updated
```

### Step 1 — Sample Generation

A sample dataset is generated by combining participant records
from multiple source sheets.

The sample serves as the reference input for matching operations
in the current processing run.

### Step 2 — JSON Loading

Multiple JSON classification files are loaded
from the Google Drive folder.

Each file contains source data with participant IDs
and associated metadata for one or more source columns.

### Step 3 — Participant Matching

Participant IDs from the sample dataset are matched
against the loaded JSON source data.

Matching logic:
- each participant ID is checked against all source columns
- matched records receive the associated source metadata
- unmatched records are identified for separate handling

### Step 4 — Progression Tracking

Matched participants are tracked across six engagement steps
(Step 1 through Step 6).

Each step:
- reads participant IDs from the designated input column
- matches IDs against the JSON source dataset
- writes matched source attributes to the step output sheet
- uses a temporary JSON file as intermediate storage
- cleans up temporary files after writing results

Steps are processed independently,
allowing each step to be run separately if needed.

### Step 5 — Results Writing

Matched results are written to step-specific output sheets
with source metadata fields mapped to designated columns.

Date fields are formatted consistently during writing.

### Step 6 — Real-time Matching (when needed)

Current participant records can be matched against
source data in real time.

Matched source attributes are written back to the input sheet,
providing immediate visibility into source channel information.

### Step 7 — Analysis Mapping (when needed)

Processed data from the analysis sheet is mapped
to a dedicated mapping table.

Formatting including backgrounds, font colors, and font sizes
is preserved during the mapping operation.

### Step 8 — Time Tracking

Time entries recorded by contributors are parsed
and aggregated into a total.

The system handles multiple time formats
and writes the aggregated total to a designated cell.

---

## Workflow Coordination

The two paths share the JSON storage layer on Google Drive:

```text
Path 1 (Source Management)    Path 2 (Matching + Analysis)
        │                               │
        ▼                               ▼
    Writes to                      Reads from
        │                               │
        └──────► JSON on Drive ◄────────┘
```

This separation means:
- source data can be updated independently of analysis runs
- the JSON dataset grows and evolves as sources change
- either path can be run without affecting the other

---

## Error Handling and Known Limitations

**Timeout handling**
Component B detects approaching execution limits
and uses time-based triggers to continue processing
across multiple runs.

**Duplicate handling**
Participant IDs are deduplicated before matching
to prevent redundant processing.

**Planned improvements**
A Python desktop application is planned to replace
the online GAS processing layer, providing:
- offline execution independent of network conditions
- more reliable error recovery for large datasets
- elimination of trigger-based continuation complexity
